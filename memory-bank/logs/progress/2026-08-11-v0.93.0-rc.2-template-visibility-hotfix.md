# v0.93.0-rc.2 部门负责人模板可见性热修

## Incident

员工实际试用 `v0.93.0-rc.1` 时，部门负责人进入任务模板页面后看不到本应对其部门可用的模板，而管理员账号显示正常。

根因不是后端 scope 数据或读取授权本身：前端在账号具备模板管理能力时，把整个列表请求切换为 `scope=manage`。该查询只返回行为人能够修改的模板；全局 ACTIVE 模板以及 scope 同时覆盖多个部门的共享模板虽可读、可实例化，但不满足部门负责人“完整 scope 均在其管理范围内”的修改条件，因此被错误地从列表排除。

## Test-first Evidence

1. 先扩展 `GraphTemplatesPanel.spec.ts`，模拟同一负责人拥有一个本部门可管理模板，同时能够读取一个跨部门共享模板。
2. 修复前定向执行得到预期红灯：共享模板行不存在、缺少可读列表请求、刷新调用数不符合双查询契约，共 3 项失败。
3. 修复后 4/4 定向测试通过，并纳入前端 64 files / 181 tests 全量回归。

## Fix

- 页面并行请求“可读 ACTIVE 模板”和“可管理模板”，按模板 ID 去重；管理查询的数据覆盖同 ID 可读摘要，以保留运行统计。
- 负责人可以看见并实例化 scope 覆盖其部门的全局/共享 ACTIVE 模板。
- 设计、复制、改名、可用部门、归档、删除和运行统计按管理查询返回的模板 ID 逐项控制，不再把页面级管理能力错误扩散到所有可见模板。
- 后端对象级授权策略未放宽：部门负责人仍不能修改全局模板，也不能修改完整 scope 超出其管理范围的共享模板。
- 修复提交：`0ca1b38`（`fix: restore department template visibility`）。

- `v0.93.0-rc.1` 保持不可变；从该标签建立隔离热修分支，不包含 RC1 之后主开发线的新功能。

- RC2 使用新的 release commit 与注释标签固定；修复提交单独回流 `main`，避免把 RC2 发布材料或旧基线覆盖主线进展。

## Remaining Trial Check

员工试用环境升级后，使用真实部门负责人账号验证：

1. 对本部门可用的全局、单部门及跨部门共享 ACTIVE 模板均显示且可正常发起；
2. 全局或超出其完整管理范围的共享模板不出现设计、复制、可用部门、归档或删除动作；
3. 本部门完整 scope 的自有模板仍可正常维护；
4. 管理员视图及模板管理功能无回归。

该复测是 RC 反馈闭环，不替代 I3-F、TLS/secret、备份恢复和正式生产变更窗口等外部门禁。
