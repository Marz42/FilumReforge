# W01/W02 检查入口

2026-09-13 用户在本任务明确授权“开始推进开发”，覆盖 W01/W02 的工程实现、独立测试服务和本地验证。该授权不覆盖目标库迁移、生产部署、外部通知或 Phase D。原 KI-014 总任务只在本次支持性工程工作期间恢复 active，交接时重新记录尚未解除的目标门禁。

## 统一入口

从仓库根目录执行。Windows 将下列 `python` 替换为 `backend\.venv\Scripts\python.exe`；Linux 可使用已安装依赖的 Python 3.12。

```bash
python scripts/check_release.py --mode developer
python scripts/check_release.py --mode isolated-ci --suite backend
python scripts/check_release.py --mode isolated-ci --suite frontend
python scripts/check_release.py --mode isolated-ci --suite smoke
python scripts/check_release.py --mode isolated-ci --suite governance
```

`bash scripts/check-release.sh` 是同一实现的兼容入口，默认 release（与不带参数的 Python 入口一致），开发检查必须显式指定 developer。所有模式均检查必需命令退出码；缺工具、空报告、错误报告、缺失 JUnit、必测跳过均失败，不再输出“生产 READY”。只允许原有 `test_services` 中准确标记 B-12 的 Legacy E 跳过；PostgreSQL 不允许任何跳过，且必须覆盖 `scripts/required_postgres_tests.json` 中约定的 22 项用例；新增测试可增补，删除或改名须同时评审这份必测清单。执行前删除该次 JUnit 文件和旧成功摘要，防止旧报告替代未执行或被中断的测试。

报告默认写入被 Git 忽略的 `verification-runs/release-check/`，可用 `--output` 指定独立目录。保存命令结果、JUnit、耗时、SHA 和 dirty 状态；日志对 DSN/secret/token 等值脱敏。开发模式不包含 PG/Redis 证据；suite 的通过只代表该 suite，不表示所有检查完成。每份汇总固定 `production_ready=false`、`human_gates_required=true`。

## 独立测试服务

```bash
docker compose -p filum-w01-checks -f infra/docker/compose.checks.yml up -d --wait
```

本机连接参数（均为可丢弃测试账号）：

```text
POSTGRES_TEST_ADMIN_DSN=postgresql://filum_test:isolated-ci-only@127.0.0.1:55432/postgres
REDIS_TEST_DSN=redis://127.0.0.1:56379/15
```

设置为当前终端环境变量后运行 isolated-ci backend。禁止将生产账号填入 `POSTGRES_TEST_ADMIN_DSN`。测试会通过随机名称创建并删除独立数据库；显式开启 `FILUM_REQUIRE_POSTGRES_TESTS=true`。应用测试不继承目标 `POSTGRES_DSN`，默认使用内存 SQLite，PG fixture 自行连接测试数据库。

服务绑定本机回环地址，镜像固定 digest；PostgreSQL 数据放 tmpfs，不挂载项目既有数据库卷。完成后可用相同项目名和同一 compose 文件执行 `down`，释放本次临时服务。

## Schema 与发布模式

```bash
python scripts/check_schema.py --isolated --allow-ki014-compatibility
```

该命令在独立空测试库执行 fresh upgrade，然后在只读事务中比较 ORM 与 DDL，最后删除该测试库。迁移仓库必须单 head，目标 revision 必须等于该 head。仅在 `20260827_01` 接受精确三项 `True → False` nullable 差异；额外操作、缺项、不同 revision 均失败，并明确报告 `schema_clean=false`。合同收缩后的 release 模式不启用此例外。

```bash
python scripts/check_release.py --mode release
```

release 要求可识别的 Git SHA 与干净工作区，并且必须运行全部 suite，并额外用应用 Settings 解析器校验 production 配置、存储目录及显式目标 DSN。目标仅执行只读 schema 比较，绝不自动 upgrade/downgrade。当前 Phase B 仍有 nullable 差异，因此不能通过最终 schema-clean 条件；需等待 Phase C 证据及独立批准的 Phase D。即使将来自动检查全部通过，也仍需 HG-04～HG-07 等人工结论。

## CI 与版本治理

`.github/workflows/check.yml` 包含 backend、frontend、governance 三个 job：Python 3.12、Node 24、固定数据库镜像、后端 constraints、前端 npm ci、最小只读权限、超时、缓存及按 SHA 命名的证据文件。前端浏览器 smoke 使用现有 mock 用例，只证明登录和外壳交互，不替代真实多账号 UAT。

治理 job 在干净 checkout 中先 dry-run/rebuild memory catalog 与文档索引两类机器缓存，再以 `git diff --exit-code` 确认没有修补已提交文档，随后运行 context、adapter 与 strict compliance。缺缓存不能跳过检查，也不能在 CI 自动修复文档后假装原提交通过。

本项目 `pd` 的规范入口为 `python scripts/pd.py`。适配器只让固定 Paradigma 0.7.0 使用 `.paradigma/VERSION`，根 Filum VERSION 保持不变；缺失协议文件、错误路径、协议/config 不一致和未经评审的工具升级仍失败。上游累计升级 Profile 的兼容性不在此适配的完成声明内。

W02 修复旧 KI-015 日志的类型/append-only 元数据，保留历史结果；为 62 份旧概念文档补正文引用或所属专题关联，补两份手册检索提示，再通过 CLI 重建索引、进度摘要和上下文。业务契约正文没有因补元数据而改变。
